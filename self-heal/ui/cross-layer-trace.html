What this surfaces that per-screen tests miss

Reading top-to-bottom is where the gaps appear — none of these are visible from any single layer alone.

L1
Shown = sent = stored = shown-back
UI formats "200,000", API sends 200000, DB stores 200000 — a locale/rounding bug can slip in any hop
Oracle — all four values are exactly equal, re-rendered summary included
L2
Calculation integrity
PV need is computed in the App layer but must match what's persisted and displayed
Oracle — pvNeed / totalNeed identical across API response, DB row, and UI
L3
Atomic total-need update
Editing or deleting a goal must recompute the total, not just the row
Oracle — total_need = Σ active goals after every add/edit/delete, never stale
L4
Audit-log completeness
Every rule-bearing advice decision must be logged for compliance review
Oracle — one audit_log row per decision, carrying rule + rate version
L5
Rate/rule version stamping
A quote must be reproducible against the exact filed rate table used
Oracle — quote pins rate_version; mid-draft rate changes are flagged
L6
Idempotency
A double-tap or retried Save shouldn't double the goal or the total
Oracle — exactly one goal row persists per logical save
L7
Referential integrity
Deleting a goal shouldn't leave dependent recommendations orphaned
Oracle — no orphan rows; dependent recommendations recompute
L8–L10
Draft persistence · concurrency · migration
Not visible in this single trace, but the same three-layer read exposes them for exit/resume, two-device edits, and schema changes
